CURRENT SYSTEM (BASELINE ARCHITECTURE)

The repository already contains a working ticket orchestration system.

Lifecycle overview:

1. Work begins as a product vision.

2. The TODO agent decomposes the work in three passes:

Strategic pass
L0 → L1

Planning pass
L1 → L2

Execution planning
L2 → L3

L3 defines executable tasks.


3. L3 tasks are written as markdown.

4. tickets.py parses those tasks and converts them into ticket JSON.


Ticket files exist in:

.github/tickets/<ticket-id>.json


Each ticket also has a state copy stored in a stage directory:

.github/ticket-state/<stage>/<ticket-id>.json


The directory determines the ticket's current stage.


tickets.py sync performs system maintenance:

• resolves dependencies
• releases expired leases
• fixes duplicates
• moves unblocked tickets to READY


Execution pipeline example:

READY
→ BACKEND
→ QA
→ SECURITY
→ CI
→ DOCS
→ VALIDATION
→ DONE


Agents claim work using lease metadata:

claimed_by
machine_id
operator
lease_expiry


Ticketer orchestrates dispatch but does not implement code.

The database becomes the distributed lock manager.

FILE MUTEX
